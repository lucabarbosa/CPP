00 Classes & Membros Estáticos

Primeiro passo saindo do C: organizar dados e comportamento dentro de uma classe, usar std::string/iostream no lugar de char*/printf, e entender membros static — dados e funções que pertencem à classe, não a uma instância específica.

Ex.ExercícioNota
ex00Megaphoneargv, std::string para maiúsculas
ex01PhoneBookbuffer estático de 8 Contact
ex02Accountmembros/métodos static compartilhados

Como é usado

padrão · membro estático compartilhado
class Account
{
    private:
        static int _nbAccounts;   // uma cópia para TODAS as instâncias
        int _accountIndex;

    public:
        static int getNbAccounts( void ); // não precisa de objeto
};

// fora da classe: static precisa ser definido uma única vez
int Account::_nbAccounts = 0;

Chama-se sem instância: Account::getNbAccounts(). É assim que PhoneBook guarda seus 8 contatos num array de tamanho fixo dentro da própria classe.

/* CPP-01 — Memória, Ponteiros e Referências */

01 Memória & Ponteiros

A base de tudo que vem depois: quando um objeto vive na stack (some sozinho) e quando ele vive no heap (você é responsável por liberar), e a diferença prática entre um ponteiro (pode ser nulo, pode mudar de alvo) e uma referência (sempre válida, vinculada no momento da criação).

Ex.ExercícioNota
ex00ZombienewZombie (heap) vs randomChump (stack)
ex01Zombie Hordearray dinâmico de objetos
ex02HI THIS IS Jponteiro e referência da mesma variável
ex03Weapon/Humanatributo por referência vs por ponteiro
ex04Sed is for losersifstream/ofstream, string::find
ex05Harl 2.0ponteiro para método (function pointer de membro)
ex06Harl Filterswitch com fallthrough por nível de log

Como é usado

padrão · stack vs heap
Zombie randomChump( std::string name )
{
    Zombie z( name );  // vive na stack: destruída ao sair do escopo
    z.announce();
    return z;         // copiada de volta para o chamador
}

Zombie *newZombie( std::string name )
{
    return new Zombie( name ); // vive no heap: chamador deve dar delete
}

Regra prática: se você escreveu new, alguém precisa escrever delete — em C++98, sem smart pointers na caixa de ferramentas ainda, isso é 100% manual.

armadilha · ponteiro para método
void (Harl::*fn)( void ) = &Harl::debug; // sintaxe estranha, mas é isso mesmo
(this->*fn)();                          // invoca através do objeto

Ponteiro para membro não é um endereço de memória comum — ele só faz sentido junto de um objeto (this->*fn ou obj.*fn). É assim que o Harl escolhe qual método chamar a partir de uma string.

/* CPP-02 — Sobrecarga de Operadores (Ad-hoc Polymorphism) */

02 Sobrecarga de Operadores

A classe Fixed (ponto fixo, armazenado como int com bits fracionários) é o pretexto para dominar a Orthodox Canonical Form — construtor padrão, construtor de cópia, operator= e destrutor — e para ensinar um tipo a se comportar como um número nativo via sobrecarga de operadores.

Ex.ExercícioNota
ex00Fixed — formOrthodox Canonical Form básica
ex01Fixed — conversõesint/float ↔ ponto fixo
ex02Fixed — operadoresaritméticos, comparação, ++/--, min/max

Como é usado

padrão · Orthodox Canonical Form
class Fixed
{
    public:
        Fixed( void );                       // construtor padrão
        Fixed( const Fixed &other );        // construtor de cópia
        Fixed &operator=( const Fixed &other ); // atribuição
        ~Fixed( void );                      // destrutor
};

Fixed Fixed::operator+( const Fixed &rhs ) const
{
    return Fixed::fromRawBits( this->getRawBits() + rhs.getRawBits() );
}

Implementar essas quatro funções mesmo quando o compilador geraria versões equivalentes é o exercício em si — é o formalismo que o C++ herda de gerenciar recursos manualmente, como o C.

boa prática · armazenar em ponto fixo
_fixedNum = roundf( floatValue * ( 1 << _fractionalBits ) ); // float -> fixed
float Fixed::toFloat( void ) const
{ return ( ( float )_fixedNum / ( 1 << _fractionalBits ) ); } // fixed -> float

O deslocamento de bits (<<) reserva os últimos N bits do int para a parte fracionária — a mesma técnica usada em hardware sem FPU.

/* CPP-03 — Herança */

03 Herança

A hierarquia ClapTrap → ScavTrap / FragTrap ensina como classes derivadas reaproveitam atributos e métodos da base, como a ordem de construção/destruição funciona (base primeiro, derivada por último — e o inverso ao destruir) e a diferença entre protected e private.

Ex.ExercícioNota
ex00ClapTrapclasse base: HP, energia, dano
ex01ScavTrapherda + guardGate()
ex02FragTrapsegunda derivada + highFivesGuys()

Como é usado

padrão · construtor encadeado
class ScavTrap : public ClapTrap
{
    public:
        ScavTrap( std::string name );
};

ScavTrap::ScavTrap( std::string name ) : ClapTrap( name ) // chama o construtor da base primeiro
{
    _hitPoints = 100;   // depois ajusta os próprios atributos
    _energyPoints = 50;
    _attackDamage = 20;
}

Sem a lista de inicialização (: ClapTrap(name)), o construtor padrão da base seria chamado implicitamente antes do corpo do construtor derivado — não há como "pular" a base.

/* CPP-04 — Polimorfismo, Classes Abstratas e Interfaces */

04 Polimorfismo

Com Animal → Dog / Cat: funções virtual fazem o método certo ser chamado mesmo através de um ponteiro para a classe base (binding dinâmico), destrutor virtual evita vazar memória ao deletar por ponteiro base, e = 0 cria classes abstratas que não podem ser instanciadas.

Ex.ExercícioNota
ex00WrongAnimal vs Animalo bug de não usar virtual
ex01+ Braincomposição, deep copy no construtor de cópia
ex02Animal abstratavirtual makeSound() = 0;

Como é usado

armadilha · destrutor não-virtual
Animal *animal = new Dog();
delete animal; // se ~Animal() NÃO for virtual, ~Dog() nunca roda: leak

Sempre que uma classe tem função virtual e pode ser deletada por um ponteiro da base, o destrutor precisa ser virtual também.

padrão · classe abstrata
class Animal
{
    public:
        virtual void makeSound( void ) const = 0; // pure virtual: torna Animal abstrata
        virtual ~Animal( void );
};
// Animal a; -> erro de compilação: não é possível instanciar

Uma classe abstrata só existe para ser herdada — ela define o contrato (a interface) que Dog e Cat são obrigados a implementar.

/* CPP-05 — Tratamento de Exceções */

05 Exceções

Um fluxo burocrático — Bureaucrat assina Forms — usado como pretexto para exceções personalizadas (herdando de std::exception), e para o Intern, uma pequena fábrica que decide, em tempo de execução, qual formulário concreto instanciar a partir de uma string.

Ex.ExercícioNota
ex00Bureaucratexceções de grade inválida
ex01Formassinatura com validação de permissão
ex02AForm + 3 formuláriosação polimórfica por formulário
ex03Internfábrica: string → Form* correto

Como é usado

padrão · exceção customizada
class Bureaucrat
{
    public:
        class GradeTooHighException : public std::exception
        {
            public:
                const char *what( void ) const throw() override // (throw() = c++98 noexcept)
                { return ( "Grade is too high" ); }
        };
};

try { bureaucrat.incrementGrade(); }
catch ( const std::exception &e ) { std::cout << e.what() << std::endl; }

Capturar por const& (nunca por valor) evita slicing — perder a parte derivada do objeto ao copiá-lo para o tipo base durante o catch.

/* CPP-06 — Casting (Conversões de Tipo) */

06 Casting

Os quatro operadores de conversão do C++ substituem o (tipo)valor do C, cada um com uma intenção clara: static_cast (conversão segura entre tipos relacionados), dynamic_cast (descobre o tipo real em tempo de execução), reinterpret_cast (reinterpreta bits crus) e const_cast (remove/adiciona const).

Ex.ExercícioNota
ex00ScalarConverterchar/int/float/double via static_cast
ex01Serializerponteiro ↔ inteiro via reinterpret_cast
ex02Identify (A/B/C)tipo real do objeto via dynamic_cast

Como é usado

padrão · dynamic_cast com ponteiro
Base *p = generate();
if ( dynamic_cast<B *>( p ) )      // retorna NULL se não for B: nunca lança
    std::cout << "B" << std::endl;
else if ( dynamic_cast<A *>( p ) )
    std::cout << "A" << std::endl;

Só funciona em classes polimórficas (com pelo menos um método virtual) — é isso que exige a Base ter um destrutor virtual mesmo vazio.

armadilha · escolher o cast errado
// referência: dynamic_cast falha lançando, não retornando NULL
try { B& b = dynamic_cast<B&>( *p ); }
catch ( std::bad_cast& ) { std::cout << "C" << std::endl; }

Usar reinterpret_cast para "descer" na hierarquia (downcast) é comportamento indefinido — ele não checa nada, apenas reinterpreta bits.

/* CPP-07 — Templates */

07 Templates

Programação genérica: escrever uma função ou classe uma vez e deixar o compilador gerar versões para cada tipo usado, em vez de duplicar código para int, float, std::string, etc.

Ex.ExercícioNota
ex00whatever(a, b)max/swap genéricos
ex01iter()aplica uma função a cada elemento de um array genérico
ex02Array<T>classe template com operator[] seguro

Como é usado

padrão · function template com callback
template<typename T, typename F>
void iter( T *array, const size_t size, F function )
{
    for ( size_t i = 0; i < size; i++ )
        function( array[i] ); // F pode ser função, functor ou (em c++11+) lambda
}

int nums[] = { 1, 2, 3 };
iter( nums, 3, printValue<int> ); // T e F deduzidos automaticamente

Templates são resolvidos em tempo de compilação — o código do template precisa estar visível no .hpp (não em um .cpp separado), por isso não há Array.cpp.

/* CPP-08 — Containers e Algoritmos da STL */

08 STL Containers

Primeiro contato com a Standard Template Library: containers (vector, list, stack) e algoritmos genéricos (std::find) que operam sobre iteradores em vez de índices — o mesmo algoritmo funciona em qualquer container que exponha begin()/end().

Ex.ExercícioNota
ex00easyfindtemplate genérico sobre std::find
ex01Spanmenor/maior span entre inteiros armazenados
ex02MutantStackstd::stack estendida para ser iterável

Como é usado

padrão · algoritmo genérico sobre iteradores
template<typename T>
typename T::iterator easyfind( T &container, const int value )
{
    typename T::iterator result = std::find( container.begin(), container.end(), value );
    if ( result == container.end() )
        throw std::runtime_error( "Value not found" );
    return ( result );
}
// funciona tanto para std::vector<int> quanto std::list<int>, sem alterar nada

typename T::iterator é necessário porque o compilador não sabe, sem essa dica, que iterator é um tipo e não um valor estático de T.

boa prática · estender um container da STL
template<typename T>
class MutantStack : public std::stack<T>
{
    public:
        typedef typename std::stack<T>::container_type::iterator iterator;
        iterator begin( void ) { return ( this->c.begin() ); } // `c` é o container protegido do std::stack
        iterator end( void )   { return ( this->c.end() ); }
};

std::stack não expõe iteradores por padrão — o "truque" é acessar o container subjacente protegido (this->c) para adicionar iteração sem reescrever a pilha do zero.

/* CPP-09 — STL Avançada / Projeto Final */

09 STL Avançada

Três exercícios independentes que juntam parsing de entrada com containers mais expressivos: std::map para busca ordenada, std::stack para avaliar expressões, e um algoritmo de ordenação clássico — merge-insertion sort (Ford-Johnson) — implementado sobre dois containers diferentes para comparar desempenho.

Ex.ExercícioNota
ex00BitcoinExchangestd::map + lower_bound por data
ex01RPNnotação polonesa reversa com std::stack
ex02PmergeMeFord-Johnson em dois containers, comparando tempo

Como é usado

padrão · busca ordenada com std::map
std::map<std::string, double> rates; // data -> cotação, ordenado por chave

std::map<std::string, double>::iterator it = rates.lower_bound( date );
if ( it == rates.end() || it->first != date )
    --it; // sem cotação exata: usa a data válida mais próxima anterior

lower_bound encontra a primeira chave não menor que a data pedida em O(log n) — essencial quando o enunciado exige "a taxa mais próxima, sem ultrapassar a data".

padrão · avaliação com pilha (RPN)
std::stack<int> values;
for ( token in tokens )
{
    if ( isNumber( token ) )
        values.push( toInt( token ) );
    else // operador: consome os dois últimos, empilha o resultado
    {
        int b = values.top(); values.pop();
        int a = values.top(); values.pop();
        values.push( apply( token, a, b ) );
    }
}

É o mesmo mecanismo de pilha que uma calculadora HP usa — não precisa de árvore de expressão nem de parser de precedência.

saída esperada · comparação de containers
$ ./PmergeMe 9 8 7 2 3 1 5 4 6
Before: 9 8 7 2 3 1 5 4 6
After:  1 2 3 4 5 6 7 8 9
Time to process a range of 9 elements with std::vector : 0.00042 us
Time to process a range of 9 elements with std::list   : 0.00061 us

O objetivo não é só ordenar corretamente, mas evidenciar o trade-off real entre std::vector (acesso contíguo) e std::list (inserção sem deslocar memória) no mesmo algoritmo.
